# 2026-11-01 转向：放弃 Kotlin 重写，改为「原版核心 + Android 壳」

## 触发
用户指出 PC 上开系统代理就能上 Google，质疑对 dev-sidecar 分析不彻底。核实后确认：
dev-sidecar 靠 **MITM + SNI 伪装(www.google.cn) + unVerifySsl + preSetIpList** 实现，
日志实证：`sni intercept: www.google.com.hk ➜ www.google.cn, unVerifySsl`。
我们此前的"纯字节转发"永远做不到（Google 在可连 IP 上返回诱饵证书 CN=invalid.invalid，
WebView 报 net_error -202）。

## 决策
用户决定：**先不考虑精简，把 sidecar 本体完整移植到 Android**，避免功能遗落。

## 关键验证（已完成 P0）
- `@blue-frontier/dev-sidecar/src` 全目录无 require('electron')，核心纯 JS
- 原生 .node 仅 5 个：koffi / sysproxy / shutdown-handler(win32) / @parcel/watcher / keytar
- Windows 逻辑集中在 src/shell/
- **纯 Node 同进程跑通**：`node port/harness.js <app> 31282`
  → `代理服务已启动 127.0.0.1:31282 ssl=true`，自签 CA 自动生成
  → `curl -x 127.0.0.1:31282 https://www.google.com.hk` = **200 / 1.87s**
- UI 是 Electron loadFile(dist/index.html)+IPC，需换 HTTP 桥

## 发现的上游 bug
`running.json` 里 intercepts 存在 value=null 的条目（远程配置表示"停用"），
mitmproxy `script.js:139` 未判空 → **代理服务重启即崩**。移植时必须启动前 sanitize。

## P1：内嵌 Node 运行时
- 官方 nodejs-mobile 只有 Node 12.19（语法不兼容），改用 Termux nodejs-lts 24.22.1（aarch64 ELF）
- 依赖 7 个 Termux 包（libc++/openssl/c-ares/icu/sqlite/zlib/ffi），so 共 46MB
- 关键坑：RUNPATH 指向 termux 路径 → 用 LD_LIBRARY_PATH；openssl 证书路径不存在 → SSL_CERT_FILE；
  Android 10+ 不能从数据目录 exec → 二进制以 libnodebin.so 放 jniLibs + useLegacyPackaging=true
- APK 49MB：libnodebin.so 46MB + node-libs.zip 18MB + nodejs-project.zip 11MB
- 真机 runtime 未验证（USB 断开）
- 大文件下载实测：ghproxy.sakuramoe.dev / 30006000.xyz / gh.padao.fun 均 ≥5MB/s，其余多为 CF 前置不通

## EinkBro 换壳成功（03:52）
- 决策：放弃 Lightning（Compose AndroidView 里的 WebView 导致 ProxyController 静默失效），改用 EinkBro
- 结论：EinkBro 的 `EBWebView : WebView(context)` 由 Activity 直接 new，代理正常；
  **选壳铁律：WebView 必须是裸 WebView 子类，不能被 Compose AndroidView 包**
- 改动：新增 accel/DshaAccel.kt、Application.onCreate 调 start、EBWebView.init 调 ensureProxy、
  NSC 加 @raw/dsha_ca、jniLibs useLegacyPackaging、noCompress(zip/pem/crt)、release 用 debug 签名
- 实测：GitHub Trending / Google 搜索 / 百度 全部正常；release 包 48MB
- 坑1：release 上游 proguard 的 -assumenosideeffects 把 Log.i 全裁掉，看不到 dsha 日志
- 坑2：debug 变体被 LeakCanary 抢启动页，用 release 包
- 坑3：端口 31181 被旧包占用 → EADDRINUSE 秒退，测试前 force-stop 其它包
- 产物：einkbro-arm64-release.apk（工作区根目录），文档 EINKBRO.md

## Lightning 版修复成功（04:12）—— 推翻此前结论
- **主因不是 Compose AndroidView**：debug 包被 LeakCanary（debugRuntimeOnly leakcanary-android）
  抢了 LAUNCHER 入口，浏览器 Activity 从未起来，WebView 没创建 → 核心 0 请求。
  该依赖在 gradle dependency lock 里，删不掉（报 Did not resolve ... part of dependency lock state）
  → 一律用 release 变体（无 LeakCanary）
- 次因：启动即恢复标签，页面在核心端口 LISTEN 前就请求，Chromium 缓存"代理连不上"不重试
  → DshaAccel.refreshProxy()：就绪后 clearProxyOverride 再 setProxyOverride
- 三因：release 开 R8 启动崩 IllegalStateException: Unsupported type class fn4（kotlinx.serialization
  被裁坏）→ 本地自用 isMinifyEnabled=false + isShrinkResources=false（顺带保住 Log.i）
- 实测：GitHub Trending 完整渲染，核心收到 207 个请求；google.com 302→google.cn 属地域重定向
- 产物：lightning-arm64-release.apk（58MB）
