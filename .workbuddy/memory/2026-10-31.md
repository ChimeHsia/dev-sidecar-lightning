## dsha-sidecar：构建修复 + netcore 三大模块落地

**构建**
- 卡点：AGP 8.7.3 的 JdkImageTransform 调 GraalVM 的 jlink 处理 core-for-system-modules.jar 失败。
- 解法：下载 OpenJDK 21.0.2 到工作区 `.jdk/jdk-21.0.2`，`gradle.properties` 加 `org.gradle.java.home`。`android.experimental.disableJdkImageTransform` 在 AGP 8.7.3 无效。
- 产物：debug 3.3MB / release 558KB（R8 开）。

**新增代码（netcore，纯 JVM 模块）**
- `net/dns/`：DnsPacket（手写报文 + CNAME/压缩指针）、DnsClient（多上游 + TC 走 TCP + 系统解析兜底）、IpBenchmark（并发 TCP443 测速）、DnsCache（TTL + TSV 持久化）、HostResolver（编排 + 同域名串行化）。
- `net/rules/`：Rule/Policy/RuleAction（ACCELERATE/DIRECT/ABORT/PROXY）、RuleEngine、BuiltinRules（仅 GitHub 域走加速，其它直连）。
- `net/proxy/`：LocalProxyServer（127.0.0.1:8118，CONNECT + 绝对 URI）、Tunnel（半关闭）、TlsClientHello（解析 + 改写）。
- app：`accel/AccelManager`（ProxyController + 生命周期 + 状态）、MainActivity 加速开关与状态栏、network_security_config。

**关键技术结论（重要）**
- **不能在链路上改写 ClientHello 的 SNI**：SNI 参与 TLS transcript，改写导致两端不一致，TLS 1.3 在 Finished 校验报 tag mismatch。已用真实 JSSE 服务端复现并写成回归测试 `TlsThroughProxyTest.链路上改写 SNI 会导致 TLS 握手失败`。
- 因此加速 = 连更快的 IP + SNI 原样；转发器只做纯字节转发。`TlsClientHello.rewriteSni` 仅保留给"自己发起 TLS"的场景。
- JSSE 不对单标签主机名（localhost）或 IP 字面量发 SNI，写测试要用带点域名。

**测试**：28 个用例（26 pass + 2 联网 skip），含本地真实 TLS 闭环（自签名 p12 在 `netcore/src/test/resources/tls/`）。

**待办**：真机验证（当前无设备/模拟器）、自建下载器（DownloadManager 不走代理）、多标签、书签历史、页面级 URL 改写注入。

## 真机验证（荣耀 PPG-AN00 / Android 16，校园网 NNU-WiFi6）

用 adb + uiautomator + screencap 直接操作真机验证，链路跑通。

**环境特性（重要）**
- 该网络系统 DNS 基本不可用（dns_fail_count=19），github.com 报 ERR_NAME_NOT_RESOLVED
- UDP 53 被拦截（4 个公共 DNS 全超时）；TCP 443 到 GitHub IP 正常（76–110ms）
- 部分站点被 TLS 中间人（example.com 证书链校验失败）

**为此改的代码**
1. `DnsClient` 加 DoH 兜底（`https://223.5.5.5/dns-query`，HttpURLConnection，零依赖），并记住上次成功通道 `preferDoh`；首包只试一个 UDP 上游，失败立刻转 DoH，避免 5s 空等。
2. `HostResolver.resolveQuick()`：普通域名只解析不测速；代理的 DIRECT 分支也走自建 DNS——否则系统 DNS 坏掉时普通网页打不开。
3. 修 `LocalProxyServer` 线程池：core=0 + 无界队列只会创建 1 个线程 → 改成 core=max=64 + allowCoreThreadTimeOut，页面才不再卡住。
4. 修 edge-to-edge：targetSdk 35 下必须 `setOnApplyWindowInsetsListener` 让出系统栏，否则工具栏被状态栏压住（点地址栏点到状态栏）。
5. 状态栏 ticker 在自动启动路径也要跑；状态里加失败数。
6. 加日志 tag `dsha-accel` / `dsha-ui`，`Tunnel` 返回双向字节数用于判断"连上但没数据"。
7. 连接超时 6000 → 4000ms。

**验证结果**：GitHub 首页完整渲染（图片/CSS 都在），状态栏 `请求 7 · 加速 5 · 最近 api.github.com → 20.205.243.168（176ms）`；
另外用 `adb forward` + Python ssl 独立验证隧道：CONNECT 200 → TLS1.3 → CN=github.com → HTTP 200，0.7s。

**学到**：WebView 的 preconnect 会"连上不发数据就关"，日志 0B 0B 属正常。

## 追问 dev-sidecar 为什么能上 Google（2026-10-31 深夜）

核实了 README：
- 头号能力是 **通用 dns 优选**（任意域名可加），README 明确写"被***封杀的无效"
- github 直连加速"通过修改 sni 实现"，且**默认模式需要安装证书**（= MITM，SNI 是它自己发起上游 TLS 时用的，不是偷改浏览器字节）

真机三项实验（荣耀 PPG-AN00 + 校园网）：
1. DoH 解析 www.google.com.hk → 199.16.x/31.13.x（Twitter/Facebook IP）→ DNS 投毒
2. TCP 143.250.4.94:443 通（80ms），但 ClientHello 带 SNI=www.google.com.hk → 立刻 RST
   ⇒ 阻断在 **SNI 层**，DNS 优选无效
3. 手机有全局 IPv6，但到 Google IPv6 也不通

结论：手机上要上 Google 只能靠"中转"，超出"不改 TLS/不做 MITM"的前提。Google 域名因此默认不进加速表。

顺带修的两处健壮性问题：
- `HostResolver.invalidate` + 代理里"缓存 IP 连不上就重测一次"
- 新增 `IpSeed`：DNS 只给 1 个地址时补种子 IP（140.82.x / 20.27.x 等），仍要测速。
  实测 github.com 命中 20.27.177.113（52ms），救回了当晚 SG 节点失联的情况。
